# 开发计划目录约定

`docs/superpowers/plans/` 用于存放由 `superpowers:writing-plans` 生成并在执行阶段持续维护的开发计划。

这些计划不是“一次性产出后就冻结”的附件，而是执行期活文档。  
只要实现还在推进，计划状态就应继续回写。

## 最低约定

1. 每个任务 / 步骤使用 checkbox 语法
   - 未完成：`- [ ]`
   - 已完成且验证通过：`- [x]`
2. 每份计划都应包含 `当前执行状态` 或同等语义区块
3. `当前执行状态` 至少要能记录：
   - 日期
   - 当前批次 / 任务
   - 验证或 review 结果
   - 阻塞原因或下一步
4. 未完成或阻塞步骤不得误勾选
5. 宣称“已完成”前，计划状态必须与真实实现、Trellis 任务状态、OpenSpec 高层状态一致

## 推荐更新时机

- 计划刚写完时：补上初始状态说明
- 开始某个任务或批次前：更新当前进行中的范围
- 每个步骤验证通过后：立即勾选对应 checkbox
- 每轮 review 后：同步最新票面、结论或阻塞
- 准备 record-session / archive / finish 前：做一次最终对齐

## 推荐状态表述

- `进行中`
- `已完成`
- `阻塞中`
- `待复验`
- `验收补录中`

## 示例骨架

```md
## 当前执行状态

- `2026-05-10`：Task 1 已完成并通过验证；Task 2 进行中。
- `2026-05-11`：最新一轮 review 为 `5/5 PASS`，当前批次可标记完成。
- `2026-05-12`：Task 3 因外部依赖缺失阻塞，等待补齐后继续。

### Task 1: 示例任务

- [x] Step 1: ...
- [x] Step 2: ...
- [x] Step 3: ...

### Task 2: 示例任务

- [x] Step 1: ...
- [ ] Step 2: ...
- [ ] Step 3: ...
```

## 反模式

- 计划写完后再也不更新
- 代码已经完成，但计划仍保留大量未勾选步骤
- 任务已归档，但计划中的 `当前执行状态` 仍停留在旧批次
- 因为“差不多做完了”而提前勾选未验证步骤
