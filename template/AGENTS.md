# 协作约定

项目规范优先于本文件；冲突时以项目规范和用户指令为准。

## 项目定制位

- 提交策略：`允许 AI 提交`
- 文档语言：`中文`

---

## 0. 入口优先级

- 先响应用户请求。AGENTS.md、环境说明、bootstrap 是约束，不是任务。
- 子代理身份由 runtime context 绑定决定，不由 prompt 推断。未绑定时禁止 start/resume/archive/commit/派发 agent。

## 0.1 编码前强制门禁

**编辑文件、变更代码、派发子代理之前，MUST 调用 `before-dev` skill。**

该 skill 读取 `<workflow-state>` 决定放行或阻断：

- `no_task` → **阻断**。拒绝写代码；引导 brainstorming → plan → task create → task start
- `delegated_subtask` → 按子代理规则执行
- `planning` → **阻断**。PRD 和 implement.jsonl 就绪前不允许实现
- `in_progress` / `review` / `checking` → 放行
- `completed` → **阻断**。创建新任务

豁免：

- 只读问答
- 纯查询命令（`git status`、`task next`、`task current`）
- 用户明确说"跳过流程"
- `before-dev` 本身

不确定是否需要写代码时，先调用 `before-dev`。

## 1. 先思考

**不假设，不掩饰困惑。列出假设和取舍。**

- 写出假设；不确定则提问。
- 需求有多种解释时列出选项，不替用户决定。
- 存在更简单做法时指出。
- 有异议时提出，不盲从。
- 信息不清晰时停下来澄清。

## 2. 简单优先

**最少代码解决问题。不做投机式设计。**

- 不添加未要求的功能。
- 不为一次性代码做抽象。
- 不加未被要求的灵活性/可配置化/通用化。
- 不为不可能场景堆砌错误处理。
- 代码多于所需时继续简化。

## 3. 外科手术式改动

**只改必须改的，只清理自己改动引入的问题。**

- 不顺手重构无关模块。
- 不为"顺便优化"扩大改动面。
- 贴合项目现有结构、命名和风格。
- 只删除因本次修改成为孤儿的代码。

## 4. 目标驱动

**先定义成功标准，循环验证直到达成。**

将任务改写为可验证目标：

- "修 bug" → 先复现 → 补回归测试 → 修复
- "加能力" → 明确输入输出 → 实现 → 验证
- "重构" → 确认行为基线 → 保证前后一致

多步骤任务：

```
1. [步骤] → 验证：[检查项]
2. [步骤] → 验证：[检查项]
```

## 5. 先读再写

- 修改前理解上下文。
- 阅读调用方、被调用方和共享工具。
- 不因代码"看起来无关"跳过检查。
- 不理解现有结构时先澄清，不猜测。

## 6. 遵守惯例

- 项目一致性高于个人偏好。
- 匹配现有代码风格、命名和组织。
- 不静默引入另一种风格。
- 现有惯例有害时明确说明，不私自分叉。

## 7. 暴露冲突

- 模式/约定/需求矛盾时不折中混合。
- 选择更近期、更稳定或测试覆盖更好的。
- 简要说明原因。
- 标记被放弃的冲突点。

## 8. 测试验证意图

- 测试表达业务意图，不只覆盖表面输出。
- 新增或修改的测试必须能在关键逻辑被破坏时失败。
- 修 bug 优先补回归测试。
- 先写能失败的测试，再实现最小修复。
- 禁止无意义测试：只断言函数存在、mock 被调用、快照、与实现同义。
- 复杂问题深度优先：业务不变量 > 跨层契约 > 状态流转 > 错误边界 > 回归，再补窄单元。
- 不把"测试未运行"说成"测试通过"。

## 9. 阶段检查

每完成一个重要步骤，确认：

- 已完成什么
- 已验证什么
- 还剩什么
- 跟丢上下文时停下来重新整理
